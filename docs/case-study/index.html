Case study · distilroute · Banking77

Distilling a 120B ticket router into 22M parameters

A zero-shot LLM labelled 3,000 banking support messages. A small model trained only on those labels now routes new messages on a laptop CPU in under 3 ms. With a confidence-based fallback to the LLM, it beats the LLM on its own for a fraction of the cost.

Built for $0: free-tier LLM, free Colab GPU, laptop CPU

The setup

Banking77 is 13,083 real messages from a banking app's support inbox, each labelled by a person with one of 77 intents: card_arrival, top_up_by_card_charge, compromised_card and so on. Many intents are near-synonyms, which makes it a hard routing problem.

The teacher is gpt-oss-120b on Groq's free tier, prompted zero-shot with the 77 intent names and a one-line description of each, and no example messages. It labelled training messages. The students never see a human label. Every accuracy on this page is measured against the human labels on held-out test messages that nobody trained or tuned on.

The number that was too good

The teacher's first full run on the test set scored 0.948. The real number is 0.867.

The test file is sorted by intent, and the labeller sent messages in batches of 20. So every batch was 20 messages with the same intent, and the LLM used the batch as a hint. On the same 200 messages it scored 0.98 in sorted batches and 0.905 in shuffled ones. The labeller now always shuffles. The general lesson: when an LLM labels in batches, the batch is part of the prompt.

Let the student ask for help

After temperature scaling, a student's confidence means what it says: of the messages it is 90 % sure about, about 90 % are right. That makes a simple policy possible. The student answers when it is confident, and sends everything else to the LLM.

How many LLM calls does it take?

Each point trains the same student on a random sample of the labelled pool. Human labels keep paying off to 10,000 messages. Teacher labels flatten out near the teacher's own accuracy, because the student learns the teacher's mistakes along with its answers.

Which messages are worth an LLM call?

If you pay per LLM call, you can choose which messages to label. The usual advice is to label the ones the model is least sure about. Here that bought only half a point, because the ambiguous messages are exactly the ones the LLM mislabels: it got 19.8 % of them wrong, against 15.2 % on average.

What did work is choosing the most typical messages first: cluster all messages by meaning and label the one nearest the centre of each cluster. No model is needed, so it works before you have one.

Knowing a message is not its job

What did not work

  • Beating the teacher. Soft labels, a filter for likely-wrong teacher labels and self-training on unlabelled messages added 0.7 points together. The student still sits 1.8 points below the teacher at 3,000 labels. The data curve says more labels would close the gap sooner than more tricks.
  • Soft labels. Training on the teacher's top-3 guesses instead of its top answer made students slightly worse, on both the frozen and the fine-tuned model. With 77 near-synonym intents, the teacher's second and third guesses are more often noise than signal.
  • Uncertainty sampling, as above: the messages it picks are the ones the teacher gets wrong.
  • A bigger student. DistilBERT (67M) is no more accurate than MiniLM (22M), and it is twice as slow.

Try it, check it

The served student runs in your browser on the live demo page: type a message and see its intent, its calibrated confidence, and whether it would go to the LLM. Every number here comes from a script in the repository that can be re-run. The teacher's labels are committed, so none of it needs an API key.

Scope: this recipe covers "read a short message, pick a queue" tasks such as routing, triage and moderation. It does not cover free-text outputs like summaries or replies. Costs: the LLM at Groq's paid list price, one message per call. Students as CPU time on an AWS t3.small at on-demand price, which is an upper bound; on hardware you already own they cost nothing. Latency is single-message, in-process, on a laptop CPU.
